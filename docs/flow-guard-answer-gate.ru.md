Локальный кандидат **0.22.0**, 26 октября 2026; в npm не опубликован. Продолжение [эксперимента с четырьмя условиями](flow-guard-review-factors-2026-10-26.ru.md): удаление ошибки цены C иногда добавляло ошибку расстояния D. Удалить одно противоречие недостаточно.

## Контракт и область проверки

`createAnswerGate` экспортируется из `@aimarket/warden`. Приложение явно подключает SDK и владеет правилами из запроса пользователя/политики, нормализованным снимком записей, сессией, номером хода, вызовом модели и финальной выдачей. Кандидаты буферизуются до проверки. Инструкции внешнего сервера не становятся правилами проверки.

Каталог заменяет исходные ID и имена полей безопасными ссылками `rec-…` и `field_1`. Обратная связь содержит точную ссылку, поле, фактическое значение и границу без цитирования имён, URL и фрагментов инструкции. `referenceForRecord(sourceId)` предназначен приложению. SHA-256 связывает сессию, ход, снимок, правила и ранжирование; перестановка записей не меняет ссылки.

Модель возвращает строго четыре поля: `schema: "warden-selection/1"`, `catalogSha256`, `selectedRef`, `eligibleRefs`. Пример API и JSON приведены в [английской версии](flow-guard-answer-gate.md).

После каждого ответа проверяются **выбранная запись и все объявленные допустимыми альтернативы по всем правилам**, полнота множества допустимых записей и необязательный числовой минимум/максимум. Равные оптимальные варианты разрешены. Правила: конечные числа `lte`/`gte`, строгое числовое/булево `eq`. Пропущенные или неверно типизированные необходимые факты, устаревший контракт, неизвестные ссылки, дубли JSON-ключей, проза и дополнительные поля не дают разрешения. Если допустимых записей нет, результат удерживается.

Наружу передаются проверенные структурированные данные; значения берутся из снимка приложения. Произвольные объяснения, даты, география, истинность источника и скрытое влияние на предпочтения этим не проверяются. Нормализация единиц и выбор правил — обязанность приложения. Разрешённый ответ не разрешает платёж, действие или вызов инструмента.

## Ограниченный цикл и выдача

`gate.run({ generate, emit, maxCorrections: 2, timeoutMs: 30000 })` допускает первоначальный ответ и максимум **два исправления** — один дополнительный проход сверх прежнего одного исправления. После C→D новая проверка выдаёт факт `2.5 > 1` для D. После лимита приложение выдаёт `WARDEN_RESULT_WITHHELD`, не ошибочный кандидат. Допустимы только 0/1/2 исправления.

Экземпляр резервирует одну выдачу. Ошибки генерации, отмена и таймаут не повторяют запрос к провайдеру автоматически; поздний ответ не публикуется. Адаптер должен соблюдать `signal`, чтобы остановить собственную работу. Неопределённый результат записи в выходной канал не пересылается повторно. Приложение отвечает за владение запросом между экземплярами и не должно транслировать непроверенные кандидаты или их журналы пользователю.

Фиксированное уведомление приложения сохраняется независимо от модели. `disclosure: "source-instructions"` допустим при наличии свидетельства найденных инструкций; по умолчанию сообщается об использовании внешних записей. Приложение обязано отобразить уведомление. [Рабочий пример stdio](../examples/answer-gate-host.mjs) получает `--contract host-owned.json`, читает кандидатов построчно из stdin, пишет запросы/каталог/факты в stderr, а в stdout — только проверенный финальный результат или отказ. Сам пример не вызывает модель, API или инструменты.

**Обычный Stop-hook не владеет финальным отображением.** Его поведение с одним продолжением сохраняется. Для удержания результата требуется явная интеграция SDK с буферизацией. Проверка собственного stdio-приложения не доказывает отображение в стороннем нативном клиенте.

## Проверки и границы вывода

Материалы: `docs/evidence/launchgate-answer-gate-2026-10-26/` в монорепозитории. Сборка и тесты выполняются на Linux factory-vps. Проверяются цикл C→D→допустимый результат, удержание неисправленного D, полные множества и ранжирование, неизвестные данные, устаревание, враждебные метаданные, отмена, таймауты, конкуренция, неопределённая доставка и stdout настоящего дочернего процесса. Новых вызовов модели в этой офлайн-проверке нет.

Из 384 сохранённых ответов в новую схему переносятся только явно размеченные списки допустимости. Неподдерживаемая проза остаётся неизвестной. Отказ для закодированного ложного списка не доказывает понимание прозы, исправление новой моделью или защиту на независимом наборе. Старые ответы и результаты не изменены.

Прочитан полный сырой диалог упорного случая: итоговый текст одновременно называет C допустимым за $129 и исключает C за цену $190. Это наблюдаемая противоречивость ответа, а не доказательство внутреннего механизма ошибки. Подготовка и разбор выполнены с AI; независимая слепая проверка не заявляется.
