# Проверка серверов, которые запускают ваши MCP-клиенты

> 🌐 [English](scan.md) · **Русский** · [Español](scan.es.md) · [Français](scan.fr.md) · [中文](scan.zh.md)

`warden-mcp scan` читает уже существующую у вас конфигурацию MCP, подключается к каждому серверу из неё и проверяет определения инструментов до того, как их увидит модель. Это та же цепочка гейтов, что у [`wrap`](../README-ru.md) и у [библиотеки](integration.ru.md), только пройденная один раз по вашим конфигам, а не перед одним сервером.

```bash
npx -y @aimarket/warden@0.9.0 scan
```

```text
WARDEN scan 0.9.0 · ruleset 9 sha256-nC+ybcePE8AW… · block at high
  read .mcp.json (claude-code, 3 servers)

  ✓ allow   notes        claude-code    1 tool · score 0.90
  ✗ BLOCK   evil-notes   claude-code    1 tool · score 0.00 · TOOL_DEF_EXFIL(notes) TOOL_DEF_SECRET_REQUEST(notes)
  ! error   broken       claude-code    could not start: spawn /nonexistent/bin/server ENOENT

3 servers: 1 allowed, 1 blocked, 1 not checked, 0 skipped.
```

Без аккаунта, без API-ключа, без модели. Сетевой трафик идёт только к серверам из вашего конфига и, если передан `--histor`, к журналу HISTOR.

## Где он ищет

Без аргументов — каждый существующий файл из таблицы. Передайте файлы, чтобы проверить только их; `--project` — только файлы проекта в рабочем каталоге; `--client NAME` — один клиент.

| Клиент | Файл проекта | Файл пользователя |
|---|---|---|
| Claude Code | `.mcp.json` | `~/.claude.json` (серверы пользователя и этого проекта) |
| Claude Desktop | — | `claude_desktop_config.json` в каталоге конфигурации приложения |
| Cursor | `.cursor/mcp.json` | `~/.cursor/mcp.json` |
| VS Code | `.vscode/mcp.json` (JSONC) | `mcp.json` в каталоге пользовательских настроек |
| Windsurf | — | `~/.codeium/windsurf/mcp_config.json` |

Сервер, который конфиг запускает через `warden-mcp wrap`, проверяется как сервер за обёрткой и под тем же id пина, что использует `wrap`, поэтому дрейф относительно одобренного снимка попадает в отчёт. Выключенные записи, записи с значением `${input:…}`, которое клиент спрашивает у пользователя, и записи без `command` и `url` показываются как пропущенные и никогда не исчезают молча.

## Запуск серверов

Чтобы прочитать инструменты stdio-сервера, `scan` запускает его с командой, аргументами и окружением из конфига — ровно так, как это сделал бы клиент, — и останавливает после `tools/list`. Инструменты он не вызывает никогда. Но программа при этом всё равно выполняется. Там, где это нежелательно, например в CI на pull request, `--no-launch` проверяет только строку запуска: по записям threat feed о командах и по идентичности запуска из лок-файла.

Удалённые серверы (`url`, streamable HTTP или старый HTTP+SSE) опрашиваются по сети с заголовками из конфига. `--public-only` отказывает тем, что разрешаются в loopback, частные, link-local адреса или адрес облачных метаданных; проверяется адрес, к которому реально идёт подключение. Редиректы не выполняются.

## Вывод и коды выхода

| Опция | Что пишет |
|---|---|
| (по умолчанию) | таблицу в stdout |
| `--json` | JSON-отчёт в stdout |
| `--json-file FILE` | JSON-отчёт в файл, вместе с таблицей |
| `--sarif FILE` | SARIF 2.1.0 для GitHub code scanning; только блокирующие находки, с указанием строки сервера в конфиге |
| `--markdown FILE` | сводку со сворачиваемыми подробностями для `$GITHUB_STEP_SUMMARY` или комментария к PR |

Код `0`: ничего не заблокировано. `1`: сервер заблокирован или, с `--fail-on-error`, его не удалось проверить. `2`: ошибка использования или конфига. `--fail-on SEVERITY` сдвигает порог блокировки; `--policy FILE` принимает тот же строгий файл политики, что и `wrap`.

Учётные данные в строках запуска и URL показываются как `***`. Описания инструментов в Markdown-отчёте стоят внутри блоков кода, которые этот текст не может закрыть.

## Лок-файл: ревьюим определения, а не только команду

Строка конфига говорит, какая программа запускается. Она не говорит, что эта программа скажет вашей модели. Лок-файл записывает второе, чтобы pull request это показал.

```bash
warden-mcp scan --project --lock warden.lock.json --update-lock   # после того как прочли, что изменилось
git add .mcp.json warden.lock.json
```

`--update-lock` записывает для каждого сервера идентичность запуска и полные определения инструментов и отказывается записывать сервер, который WARDEN блокирует. Повторный запуск на неизменных серверах файл не меняет. С одним `--lock`:

- сервер, которого нет в лок-файле, блокируется (`LOCK_MISSING`);
- сервер, запускаемый иначе, блокируется (`SERVER_IDENTITY_DRIFT`);
- сервер, который теперь объявляет другие инструменты, блокируется (`TOOL_DEF_DRIFT`), а Markdown-отчёт показывает изменение диффом имён, описаний и схем.

Записи лок-файла, которые не запускает ни один конфиг, перечисляются и удаляются при следующем обновлении.

## GitHub Action

```yaml
name: MCP servers
on: [pull_request]
permissions:
  contents: read
  security-events: write   # нужно только для upload-sarif
jobs:
  warden:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: alexar76/warden@v0.9.0
        with:
          upload-sarif: 'true'
```

По умолчанию Action читает файлы проекта, не запускает stdio-серверы (эту программу выбирает pull request), отказывает непубличным адресам, использует `warden.lock.json`, если он есть, пишет сводку задания и падает на заблокированном сервере. Входы: `config`, `working-directory`, `lock`, `launch-stdio`, `public-only`, `fail-on`, `histor`, `sarif`, `upload-sarif`, `version`. Выходы: `blocked`, `servers`, `sarif`. В боевых workflow закрепляйте Action по SHA коммита.

## pre-commit

```yaml
repos:
  - repo: https://github.com/alexar76/warden
    rev: v0.9.0
    hooks:
      - id: warden-scan     # изменённые конфиги; stdio-серверы не запускаются
      - id: warden-lock     # проект соответствует warden.lock.json; stdio-серверы запускаются
```

Оба хука запускают опубликованный пакет через `npx`, поэтому в `PATH` нужен Node 20 или новее.

## Плагин Claude Code

```text
/plugin marketplace add alexar76/warden
/plugin install warden@warden
```

В начале сессии плагин проверяет серверы, которые Claude Code запускает для проекта, сообщает вам, какие из них заблокированы, а модели — только имя и код находки. Описание заблокированного инструмента никогда не попадает в контекст модели. Вызовы инструментов заблокированного сервера или заблокированного инструмента затем запрещает хук `PreToolUse`: он читает один небольшой файл и ничего не запускает. Подробности и ограничения: [claude-plugin/README.md](../claude-plugin/README.md).

## HISTOR: отдаёт ли сервер вам то же, что всем?

[HISTOR](https://histor.modelmarket.dev) — публичный журнал, который каждый день записывает определения инструментов всех удалённых серверов из официального реестра MCP. `--histor` задаёт ему один вопрос о каждом удалённом сервере: тот ли это набор инструментов, который видит HISTOR?

Что отправляется: адрес эндпоинта — только схема, хост и путь (без query, без имени пользователя и пароля) — и дайджест набора инструментов по [MTL/1](https://github.com/alexar76/awr). Ни описаний инструментов, ни заголовков, ни stdio-серверов. Эндпоинты на частных хостах и адресах, а также пути, похожие на содержащие ключ, не отправляются вовсе; отчёт объясняет почему.

| Ответ | Значение |
|---|---|
| `same` | Вам отдали тот набор, который HISTOR видит сейчас |
| `different` | HISTOR никогда не видел этот набор: он изменился после последнего ежедневного обхода, или сервер отдаёт вам не то, что публичному краулеру. Попадает в отчёт как рекомендательная находка `HISTOR_UNSEEN_TOOLSET` |
| `previously-observed` | Набор, который HISTOR видел раньше, но не текущий. Рекомендательная находка `HISTOR_OLDER_TOOLSET` |
| `not-listed`, `not-observed` | HISTOR не знает этот эндпоинт или ещё ни разу не прочитал его успешно |

Ответы HISTOR никогда не блокируют. Если HISTOR недоступен, это попадает в отчёт, а проверка продолжается.

## Чего scan не делает

- Он читает определения один раз. Сервер, изменившийся позже, поймает следующий запуск, лок-файл в CI или `wrap` при каждом вызове.
- Он не проверяет аргументы и результаты вызовов, prompts и resources и не является песочницей: запуск stdio-сервера выполняет его.
- Его вердикты — это статические правила и записи угроз WARDEN. Перефразировка, которую не покрывает ни одно правило, пройдёт; что правила ловят и как часто ошибаются — в [цепочке гейтов](gates.ru.md) и в [полевом замере](mcp-survey.ru.md).
