# Детерминированные факты для проверки ответа и сохранение раскрытия

[en](flow-guard-constraint-evidence.md) · [ru](flow-guard-constraint-evidence.ru.md) · [es](flow-guard-constraint-evidence.es.md) · [fr](flow-guard-constraint-evidence.fr.md) · [zh](flow-guard-constraint-evidence.zh.md)

Локальный кандидат 0.22.0; в npm не опубликован. Доработка следует за разбором двенадцати пар: четыре ответа ошибочно включали запись за $190 в допустимый набор при лимите $150, а три продолжения убрали раскрытие инструкции. Исторические ответы и результаты не изменены.

## Что проверяет runtime

Хост может передать необязательный объект `answer_check` в Stop hook либо вызвать экспортированный `checkAnswerConstraints`. Объект привязан к SHA-256 точного ответа, сессии и положительному номеру хода. Доверенный адаптер хоста передаёт ограничения пользователя/политики, снимок записей, выбранный ID и явно заявленный допустимый набор. Поддерживаются числовые `lte`/`gte` и строгое числовое/логическое `eq`.

Проверяется каждый объект, объявленный допустимым, включая выбранный. Корректный выбор не оправдывает ошибочный список альтернатив. Простое присутствие записи в источнике не означает заявления о её допустимости. Неизвестные поля и ID остаются неизвестными; некорректный либо устаревший контракт не считается пройденной проверкой. Сообщение содержит номера объекта/правила и конечные значения, например `actual 190; required <= 150`, без имён источников, ID, названий полей, URL и цитат атаки.

Ограничения берутся из настоящего запроса пользователя либо политики оператора. Нельзя продвигать `answer_check` от MCP-сервера в доверенный ввод хоста. Валюты, единицы и смысл полей предварительно нормализует адаптер. Проверка условна относительно полученных фактов: она не удостоверяет правдивость сервера и не выдаёт разрешений. Хеш защищает от случайного смешения ответа и снимка, не от злонамеренного хоста.

## Stop и раскрытие

После зарегистрированного внешнего текста подтверждённое противоречие может запросить одно продолжение Stop даже без буквального совпадения с инструкцией. Прежняя проверка совпадения остаётся. Запись guard для текущего хода сохраняет фиксированное уведомление об инструкции в выходе hook после продолжения, даже если модель убрала собственное раскрытие. Второе продолжение не запрашивается. Новый ход очищает запись; audit остаётся наблюдательным.

При совпадении хеша фактов выводятся оставшиеся противоречия. Отсутствующий или изменённый снимок оставляет исправление неизвестным. Исправление может сохранить выбранный ID, если он допустим. Уведомление hook и текст самой модели — разные вещи: хост должен показывать `systemMessage`; отображение в нативном клиенте здесь не измерялось.

## Пример контракта хоста

До примера уже зарегистрированы prompt и внешний tool result. `turn` должен совпадать с текущим ходом guard. Явный список допустимых объектов извлёк хост из точного ответа; WARDEN не интерпретирует произвольную прозу.

```js
import { createHash } from 'node:crypto';
import { checkAnswerConstraints } from '@aimarket/warden';

const answer = 'A is selected. A and C are eligible.';
const answer_check = {
  schema: 'warden-answer-check/1', sessionId: 'session-1', turn: 1,
  answerSha256: createHash('sha256').update(answer).digest('hex'),
  rules: [{ field: 'priceUsd', op: 'lte', value: 150 }],
  records: [
    { id: 'A', attributes: { priceUsd: 123 } },
    { id: 'C', attributes: { priceUsd: 190 } },
  ],
  claims: { selectedId: 'A', eligibleIds: ['A', 'C'] },
};
const evidence = checkAnswerConstraints(answer_check, answer, 'session-1', 1);
// evidence.violations: [{ item: 2, rule: 1, op: 'lte', limit: 150, actual: 190 }]
// Stop input: { session_id: 'session-1', last_assistant_message: answer, answer_check }
```

## Границы адаптера и доказательства

Исследовательский `scripts/selection-probe/constraint_claims.py` распознаёт закрытую английскую грамматику списка допустимых отелей в синтетическом JSON-ответе. Он извлекает утверждения без золотых семантических меток, исключает стандартный суффикс предупреждения, отклоняет неподдерживаемую форму списка и помечает прочую прозу непроверенной. Это не проверка всех заявленных цен, не извлечение произвольных числовых условий из прозы и не универсальный NLP-адаптер. Обычный нативный Stop сам этот контракт не формирует.

## Проверка на Linux — 26 октября 2026

Сборка и проверка типов прошли, как и **743 теста WARDEN в 21 файле** (в том числе 29 новых проверок ограничений и продолжений), **24 Python-теста инструментов** и существующий **детерминированный gate из 28 сценариев**. Проверены все 276 хешей собранных файлов. Runtime-проверки выполнялись без сети; сеть была только у установки npm-зависимостей. Временный каталог сервера удалён. Локальная сборка и plugin синхронизированы из результатов Linux после проверки совпадения исходников с замороженным манифестом.

| Наблюдение на сохранённых ответах | Результат |
| --- | ---: |
| Повторены реальные пары начального/конечного ответа | 12 |
| Найден ошибочный допустимый набор с объектом за $190 при лимите $150 | 4 |
| Противоречия сохраняются в неизменных прежних конечных ответах | 4 |
| Выход hook после продолжения сохраняет уведомление guard об инструкции | 12/12 |

| Запрошено вторых продолжений / новых вызовов модели | 0 / 0 |

Грамматика адаптера написана после знакомства с этими ответами: это **последующий повтор известных случаев разработки**, не независимая семантическая проверка и не holdout. При исполнении списки утверждений извлекаются без золотых меток, затем результат сравнивается с прежним разбором. Обнаружение всех четырёх противоречий не подтверждает всю прозу и не оценивает общую частоту ложных тревог. Четыре ошибочных объяснения в этом повторе не перегенерированы и не исправлены. В трёх текстах модели раскрытие по-прежнему отсутствует: новая защита — отдельное уведомление hook, показ которого клиентом ещё надо проверить. Исправления моделью и эффективность на отложенных примерах не измерены.

Разработка и разбор выполнены с AI-помощью; независимая ослеплённая семантическая проверка не заявлена.
