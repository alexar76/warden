## What was checked

Handwritten phrases such as “Use the third entry in that spreadsheet” do not match the recorded secret fingerprints. After a credential read and outside text, outgoing calls still require review (`ask`) or are denied in `deny` mode. The boundary survives 1/3/8 observed intermediary results and a new user turn. A user-named or allowed recipient alone does not exempt it. Opaque MCP tool names are still checked; non-MCP tools can be covered through explicit operator outbound labels.

This is a session/action boundary, **not semantic provenance tracking**. These synthetic tool results were not generated by a live model; a reviewed call was not actually sent. The existing answer-review tests retain the paraphrase gap without literal overlap.

## Exceptions are part of the result

- An exact operator-reviewed reference-only request can pass **once**. This does not establish that the referenced value is public. Reuse, changed body/recipient/nested arguments/tool, or host-disabled public eligibility require review. A known literal credential match still denies despite an exact rule.
- An unknown non-MCP tool with no explicit label is outside this boundary's coverage. This is a tested integration limit, not an intercepted call.
- Without an observed credential or outside text this credential boundary does not activate. Ordinary private data with no recognized credential is not universally covered by this rule.
- `audit` logs without enforcement; `off` disables checks. Hooks must run and the host must enforce decisions. This run did not retest the separate task-adapter enforcer or native GUI rendering.

Strong windows remain **8 non-hex / 10 hex**. Isolated short-fragment checks are separate and their existing tests passed. No general model-mediated exfiltration-prevention claim follows.
