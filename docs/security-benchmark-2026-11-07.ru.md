## Пороги и знаменатели

Пороги: WARDEN — штатное `allow: false` static-scan/threat-feed; mcp-audit — находки определения `HIGH` / `CRITICAL` полного pipeline; mcp-shield — `HIGH Risk`; truecopy — native HIGH/CRITICAL-сигналы; mcpsentry — `HIGH` / `CRITICAL`. У truecopy любая находка, даже advisory, может означать poisoned/скрытие proxy; HC — не весь объём скрытого содержимого, а unpinned/cold-lock — отдельная политика.

Общая колонка означает **HIGH/CRITICAL-сигнал**, а не одинаковую блокировку. У WARDEN есть штатный allow/block, у truecopy классификация связана со скрытием инструмента proxy. mcp-shield может завершиться с кодом 0 при находках; mcpsentry возвращает 1 только при critical, а high-only может вернуть 0. Их сигналы не называются принудительными блокировками.

Разделять **пороговый сигнал**, **ниже порога/advisory-only**, **нет находок**, **error/partial**, **skipped**, **not run**. Любая находка включает пороговые. Шум пути стенда, конфигурации и первого baseline сохраняется и исключается по одинаковому правилу для всех.

Диагностика normalization-v1 сохранена: она ошибочно исключала три действительных SSH critical-находки WARDEN threat-feed, выбирая только static-scan. В normalization-v2 учитываются все gates определений; raw-вердикты неизменны, повтор движка не требовался. В наблюдавшихся данных WARDEN исключено только info `TOOL_DEF_UNPINNED`. Правило исключения стенда/запуска/baseline применяется ко всем продуктам, иначе any-signal от первого pinning бессмысленно равнялся бы 100%. Показываются HC-сигналы, любой релевантный сигнал и advisory-only = any − HC.

Для каждого сканера/когорты: запланировано `N`, полных результатов `C`, порогово-положительных `B` (имя поля JSON), ниже порога/advisory-only `A`, ошибок/partial `E`, пропусков `S`, незапущенных `U`; `N = C + E + S + U`, `C = B + A + no-finding`. Частота пороговых сигналов — `B/C`; recall это только для размеченной когорты атак. Покрытие — `C/N`, с исходными числами. При ошибках также показать `B/N`, не записывая ошибки в истинно отрицательные. Принудительная блокировка — отдельный продуктовый результат. Для false positive нужны метки/оценка; неоднозначные случаи — отдельно.

MCPTox-атаки — по определениям; чистый MCPTox, корпус и carryover — по снимкам серверов; HISTOR — по package target. Цель порогово-положительна при хотя бы одной релевантной находке выбранного уровня. Число находок по инструментам — дополнительная диагностика.
